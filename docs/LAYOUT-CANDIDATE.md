# Resident placement candidate

`src/csl_llm/layout.py` constructs and audits an explicit192×210 application rectangle (40320 positions). This is a candidate, not a full-model compiler/runtime qualification. It covers all290 checkpoint tensors once, with shared embedding/LM-head storage. Every matrix tile has128 outputs and112 input features, storing28672 bytes of original BF16 weights. This factorization aligns outputs with pairs of64-dimensional heads, exactly divides hidden896 into8 input shards, and reduces per-column setup work. Logical weight tiles are packed column-major for the measured DSR3/4 kernel.

Twenty-four64×20 layer regions form3 columns and8 rows. Each region places UP/GATE in two16×19 rectangles, DOWN in22×14 (44 input shards arranged22×2 for each output group), and Q/K/V/O in8×16. The remaining two11×6 regions hold64 active KV stripes per head plus two participating padding PEs each. A KV stripe stores32 positions ×64 features ×K/V in FP32 (16384 bytes), supporting2048 positions per head. All24 layers' KV allocation is50331648 bytes. Each layer has a separate control PE for norms and state. The shared embedding/LM-head region follows in192×50, with one model-control PE in unused space.

Version2 lists exact bias output-root owners and slice intervals; norm owners are explicit control coordinates. The geometric audit checks coordinate uniqueness, full matrix slice coverage, parameter totals and KV stripe coverage. It does not validate packet routes, collective partitions, DMA ownership, task/color/queue allocation or stack depth. Unassigned positions may still be required for routing/communication.

Estimated decode budgets are47552 bytes per matrix PE and40120 per KV PE, including explicit code, task-table and stack allowances. These estimates are deliberately separate from actual linked local-kernel34800-byte results. Adding SDK collectives and complete operators must fit and execute in actual tests. Matrix allowance has only1600 bytes remaining, so any extra buffer/role state requires an updated budget or changed placement. Actual ELF reports enumerate high-address SDK configuration sections separately; no allocatable section is silently discarded.

Prefill batch/workspace selection is not settled. Batch16 would exceed these local budgets. Initial correctness can use sequential resident token processing; a small batched prefill candidate must be compiled and measured with all scratch/communication buffers before claiming support or performance. No model layer or weight is silently moved to CPU computation. The intended weights and KV remain resident. Host packing/loading is separate from neural-network computation.

SDK cost remains a first-class constraint. The full-grid64×64 diagnostic was deliberately interrupted at534.71s and remains unsuccessful. Its observed host stage does not separate device execution wait, simulation overhead and transport. A later sampled run qualifies only sampled outputs and its explicit cost scope. Large resident-model simulation is not declared feasible from aggregate SRAM alone.
